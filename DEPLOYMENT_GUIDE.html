📘 Deployment Guide · v1.1

🚀 คู่มือคัดลอกระบบ CE F.A.I.R. ไปยังอาคาร/ห้องปฏิบัติการอื่น

แบบจับมือทำทีละขั้นตอน (step-by-step) สำหรับผู้ดูแลที่ต้องการนำระบบแม่แบบไปติดตั้งที่อาคาร/สาขาใหม่ด้วยตนเอง — แม้ไม่เคยใช้ Apps Script มาก่อนก็ทำตามได้

🕒 รวม ~1.5–2 ชม. 📑 16 ขั้นตอน 👤 ผู้ดูแลระบบ/IT 🌐 Apps Script + Google Sheet

👋 สำหรับผู้ที่ไม่เคยใช้ Apps Script มาก่อน

Apps Script คือเครื่องมือฟรีของ Google ที่ฝังอยู่ใน Google Sheet/Docs/Slide — ให้คุณเขียนโค้ด JavaScript รันฝั่งเซิร์ฟเวอร์ของ Google ได้โดยไม่ต้องตั้งเซิร์ฟเวอร์เอง ระบบ CE F.A.I.R. ใช้ Apps Script ทำหน้าที่ "backend" ทั้งหมด (ส่งอีเมล สร้างปฏิทิน อัปโหลดไฟล์ ฯลฯ)

สิ่งที่คุณต้องรู้พื้นฐานมีแค่นี้:

📄 Google Sheet = ฐานข้อมูลของเรา ⚙️ Apps Script = สมองกล/ตรรกะ 🌐 Web App = หน้าเว็บที่ผู้ใช้เปิด 🔑 OAuth Consent = ขออนุญาตเข้าถึงบริการ Google ⏰ Trigger = ตั้งเวลาให้รันอัตโนมัติ

📖 คู่มือนี้จะพาไปทีละคลิก — ไม่ต้องเขียนโค้ดเอง แค่ คัดลอกไฟล์, กดปุ่ม Run, ตั้งค่า ตามลำดับ หากติดขัดข้อไหน ดู Troubleshooting (ข้อ 16) ท้ายเอกสาร

เตรียมบัญชี Google กับสิทธิ์ที่ต้องมี

~5 นาที
  • ใช้บัญชี Google ขององค์กร (โดเมนเดียวกับแม่แบบ) เพื่อให้ webapp.access=DOMAIN ทำงานถูก
  • ขอสิทธิ์ Editor บน Spreadsheet ใหม่ + เข้า Apps Script Editor ได้
  • ยืนยันรายชื่อ: Owner (ผู้ดูแลหลัก) / Editor (ผู้ช่วย) / Viewer (เจ้าหน้าที่ตรวจ)
💡 แนะนำ ตั้งบัญชี Service Owner ร่วมกัน (เช่น lab-admin@org.ac.th) เพื่อไม่ให้เฉพาะบุคคลเดียวค้นหาไฟล์
✅ Checkpoint: ผู้ดูแล + สิทธิ์พร้อม

ใส่ข้อมูลพื้นฐาน: Rooms, Advisor, DivisionStaff, LabHead, Admin

~15 นาที · 5 ชีต
🟡 สำหรับมือใหม่

หลังจากข้อ 6 ระบบจะสร้างชีตว่างๆ ไว้ 10 แท็บ แต่ยังไม่มีข้อมูล — ขั้นตอนนี้คือการ เพิ่มข้อมูลอ้างอิง (master data) ที่ระบบจะใช้ตรวจสิทธิ์/ส่งอีเมล/แสดง dropdown

เปิด Sheet CE-FAIR-XXX ที่สร้างไว้ในข้อ 2 — จะเห็นชีต 10 แท็บเรียงกัน

📍 ขั้นที่ 5: (ถ้ามี) ชีต Users สำหรับ sync จาก Google Workspace

Checkpointเปิด Sheet แต่ละแท็บแล้วเห็นข้อมูลครบ — ลองกรองคอลัมน์ Email ดูว่าไม่มีช่องว่าง/ตัวสะกดผิด

  • ชีต Advisor มีอีเมลอาจารย์ครบ

ปรับ Settings (อีเมล, prefix, retention)

~5 นาที · ชีต Settings
🟡 สำหรับมือใหม่

ตั้งค่าต่อไปนี้ให้ตรงกับอาคาร/หน่วยงานใหม่ — ที่เหลือใช้ค่า default จากแม่แบบได้

Keyตัวอย่าง Valueคำอธิบาย
ADMIN_EMAILadmin-ce-b02@kku.ac.thอีเมล Admin หลักที่จะรับแจ้งเตือนข้อผิดพลาด/คำขอที่ต้องตรวจ

📍 ขั้นที่ 3: (ไม่บังคับ) ค่าที่ใช้บ่อย

  • SUPPORT_PHONE — เบอร์โทรติดต่อเจ้าหน้าที่ แสดงในหน้าช่วยเหลือ
  • SUPPORT_EMAIL — อีเมลสำหรับผู้ใช้ติดต่อสอบถาม
  • ANNOUNCEMENT_BANNER — ข้อความประชาสัมพันธ์ (ถ้ามี) แสดงบนหน้าเว็บ
Checkpointเปิดชีต Settings แล้วเห็นแถวข้อมูลครบทุก key — ลองค้นหา ADMIN_EMAIL ด้วย Ctrl+F ยืนยันว่าตั้งค่าถูกต้อง
ระวังอย่าลบแถวในชีต Settings โดยไม่ตั้งใจ — ถ้าลบ key ที่จำเป็น ระบบจะใช้ค่า default แทน ซึ่งอาจไม่ตรงกับอาคารใหม่
  • ตั้ง ADMIN_EMAIL ของอาคารใหม่
  • ตั้ง REQUEST_ID_PREFIX ที่ไม่ซ้ำกับอาคารอื่น
  • ตั้ง DATA_RETENTION_MONTHS ตามนโยบายองค์กร

ติดตั้ง Trigger รายวัน

~5 นาที · ฟังก์ชันใน Apps Script
🟡 สำหรับมือใหม่

Trigger คือ "นาฬิกาปลุก" ที่บอกให้ Apps Script รันฟังก์ชันอัตโนมัติตามเวลาที่ตั้ง — ไม่ต้องเปิดเครื่องทิ้งไว้ Google จะรันให้เอง

📍 ขั้นที่ 1: เปิด Apps Script Editor

จาก Google Sheet → Extensions → Apps Script (เหมือนข้อ 3)

CE-FAIR-SCI-B02 — Apps Script
// Editor จะเปิดแท็บใหม่ มีไฟล์: 📄 Code.gs ← ไฟล์ที่คัดลอกมาจากข้อ 4 📄 Index.html ← หน้าเว็บ 📄 JavaScript.html 📄 Stylesheet.html 📄 ReviewModal.html

📍 ขั้นที่ 2: เลือกฟังก์ชัน setupDailyTriggers

  1. ในแถบด้านบนของ Editor จะมี dropdown ข้างปุ่ม ▶️ Run — ให้คลิกแล้วเลือก setupDailyTriggers (พิมพ์ค้นหาได้)
  2. กดปุ่ม ▶️ Run
  3. ครั้งแรก Google จะขอ Authorize access → กด Review Permissions → เลือกบัญชี → Allow
Apps Script Editor
ฟังก์ชัน: [setupDailyTriggers ▼] ▶️ Run ↓ ครั้งแรกจะเห็น popup: ┌─────────────────────────────────────┐ │ Authorization required │ │ This project requires your permission │ │ to access your data. │ │ [Review Permissions] │ └─────────────────────────────────────┘
ถ้าเจอหน้า "This app isn't verified"ไม่ต้องตกใจ — เพราะ Apps Script ที่เราเขียนเองยังไม่ผ่าน Google verification (ใช้เวลานาน) ให้กด Advanced → Go to (project name) (unsafe) แล้ว Allow ได้เลย ปลอดภัยเพราะเป็นโค้ดที่เราเขียน/คัดลอกเอง

📍 ขั้นที่ 3: ตรวจผลลัพธ์

หลังรันเสร็จ ดู Execution log ด้านล่าง — ถ้าสำเร็จจะเห็นข้อความ:

    {"function": "sendPendingApprovalReminders", "schedule": "ทุกวัน 08:00"},
    {"function": "applyDataRetentionPolicy", "schedule": "ทุกวัน 02:00"}
  ]
}

คลิกไอคอน ⏰ (Triggers) ที่แถบซ้ายของ Editor → จะเห็นรายการ Trigger ที่ติดตั้ง:

ฟังก์ชันเวลาทำหน้าที่
updateExpiredRequestsทุกวัน 01:00เปลี่ยนสถานะคำขอที่หมดเวลา → Expired
applyDataRetentionPolicyทุกวัน 02:00ลบรูป/ข้อมูลเก่าเกิน retention
sendPendingApprovalRemindersทุกวัน 08:00ส่งอีเมลเตือนผู้อนุมัติที่ค้าง
ถ้ารันแล้วไม่เห็น Triggerให้ดูในแท็บ Executions (ไอคอน ⏱️) — ถ้าเห็น Failed ให้คลิกเข้าไปดู error แล้วแก้ตามนั้น ปัญหาที่พบบ่อย: สิทธิ์ OAuth ไม่ครบ (ดูข้อ 13) หรือโค้ดมี syntax error
หมายเหตุTrigger จะรันตาม เขตเวลาของโปรเจกต์ (ตั้งใน appsscript.json — ปกติ Asia/Bangkok) หากต้องการเปลี่ยนเวลา ให้ลบ trigger เดิมใน Triggers panel แล้วรัน setupDailyTriggers() ใหม่หลังแก้โค้ด
  • เลือก setupDailyTriggers ใน dropdown
  • กด ▶️ Run + อนุญาตสิทธิ์
  • ดู Execution log → success: true
  • ตรวจ Triggers panel เห็น 3 รายการ
